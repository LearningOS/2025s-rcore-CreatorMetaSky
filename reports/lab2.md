# 编程作业

1. **sys_get_time**

  - 首先把ts 变量用户态虚拟内存，转换内核态的物理内存
  - 通过 get_time_us 获取到时间，并通过字节拷贝的方式赋值给 ts 变量的物理内存
  
2. **sys_trace**

  - 读取内存 - 需要转换地址空间
  - 写入内存 - 需要转换地址空间
  - 获取系统调用次数 - 不变
  
3. **内存映射**
  
  思路是每个 TaskControlBlock 有自己的 MemorySet (内存地址空间)，每个 MemorySet 里有一个 PageTable 管理所有的页表项和 MapArea 映射关系
  
  - mmap - 根据虚拟地址空间的起始和结束，创建一个 MapArea，然后再区间内逐个建立虚拟地址到物理地址的映射关系，使用的是 PageTable map 方法
  - unmap - 根据地址空间的起始和结束，找到 MapArea 并清除掉， 同时在 PageTable 中也会映射到具体的页表项进行清空操作
  - PageTable 中的 `find_pte_create` | `map` | `unmap` 方法是理解内存映射的关键

# 简答题

## 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

SV39 页表的页表项为 64 位：

- [0:7] - 标志位
- [8:9] - 保留位 (RSW，必须是 0)
- [10:53] - 这 44 位是物理页号 (9 + 9 + 26)
- [64:53] - 高 10 位是保留位

其中高44位的物理页号可以通过虚拟地址高27位的三级索引从页表项中遍历查找到。

结构图如下：

![页表项结构](https://learningos.cn/rCore-Tutorial-Guide-2025S/_images/sv39-pte.png)

标志位作用如下：

- 0 位 V： 仅当 V(Valid) 位为 1 时，页表项才是合法的；
- 1-3 位 R/W/X： 分别控制索引到这个页表项的对应虚拟页面是否允许 读/写/取 值；
- 4 位 U： 控制索引到这个页表项的对应虚拟页面是否在 CPU 处于 U 特权级的情况下是否被允许访问；
- 5 位 G： 我们不理会；
- 6 位 A(Accessed)： 记录自从页表项上的这一位被清零之后，页表项的对应虚拟页面是否被访问过；
- 7 位 D(Dirty)：则记录自从页表项上的这一位被清零之后，页表项的对应虚拟页表是否被修改过。

## 缺页

### 请问哪些异常可能是缺页导致的

- **StorePageFault (存储页错误)** - 当进程尝试向一个未映射或只读的页面执行写操作时触发
- **LoadPageFault (加载页错误)** - 当进程尝试从未映射的页面读取数据时触发
- **StoreFault/LoadFault (存储/加载错误)**
  - 这些是页错误的更通用形式，可能包含：
     - 权限不足的访问（用户态访问内核页）
     - 对齐错误（如非对齐的原子操作）
     - PMP（物理内存保护）违规

具体对应的代码部分：
```rs
// os/src/trap/mod.rs

// ... existing code ...
Trap::Exception(Exception::StoreFault)
| Trap::Exception(Exception::StorePageFault)
| Trap::Exception(Exception::LoadFault)
| Trap::Exception(Exception::LoadPageFault) => {
    println!("[kernel] PageFault in application, bad addr = {:#x}, bad instruction = {:#x}, kernel killed it.", stval, cx.sepc);
    exit_current_and_run_next();
}
// ... existing code ...
```        

### 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略

- sepc - 保存触发异常时的指令地址。
- scause - 异常类型
- stval - 保存导致异常的虚拟地址。

### Lazy 策略有哪些好处

- 延迟分配：仅在页面首次被访问时才真正分配物理内存和建立页表映射，从而减少不必要的内存分配和页表操作
- 节省资源：如果一个进程申请了大块内存（例如 10G，但实际上只使用了其中很小一部分
- Lazy 策略可以避免浪费大量物理内存和管理开销

### 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？

1. **基本参数**：
  - SV39采用三级页表结构
  - 每个页表项(PTE)占用 8 字节 - 64 位
  - 每级页表有512个条目(2^9)
  - 标准页面大小4KB - 页表大小

2. **计算过程页表和PTE数量**：
   - 10GB内存 = 10 * 1024^3 bytes
   - 页面数 = 10GB / 4KB ≈ 2,621,440个页面
   - 每个页面需要1个PTE → 共需2,621,440个PTE

3. **页表占用**：
   - 最坏情况(完全展开的三级页表)：
     - 第三级页表：2,621,440个PTE ≈ 5,120个页表(每个页表512PTE)
     - 第二级页表：5,120 / 512 ≈ 10个页表
     - 第一级页表：1个页表
     - 总页表数 ≈ 5,131个
     - 总内存 ≈ 5,131 * 4KB ≈ 20.5MB

通过以上步骤推论，内存占用大概在 20MB 左右

### 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现

实现Lazy策略及缺页处理的核心思路如下：

1. **Lazy分配基本原理**：

- 进程申请内存时仅建立虚拟地址映射
- 实际物理页帧暂不分配（页表项标记为无效）
- 首次访问时触发缺页异常进入异常处理流程

2. **执行流程**：

```text
触发缺页 → 陷入内核 → 检查访问合法性 → 分配物理页 → 建立映射 → 重试指令
```

3. **缺页处理关键点**：

- 通过scause获取缺页异常类型（读/写/执行）
- 从stval获取故障地址
- 检查地址是否在合法区间（堆/栈/映射文件等）
- 对于合法访问：
  * 分配物理页帧
  * 初始化页面（清零或加载文件内容）
  * 设置有效页表项 PTE
  * 恢复执行出错的指令
  
### 缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。此时页面失效如何表现在页表项(PTE)上？          

当采用swap策略时，页面失效在页表项(PTE)上的表现主要通过以下机制实现：

1. **PTE有效位(V位)**
   - 被换出的页面会将PTE的`V`(Valid)位设为0
   - 当前代码中触发缺页时会检查该标志位：

```rs
// os/src/trap/mod.rs

// ... existing code ...
| Trap::Exception(Exception::LoadPageFault) => {
    println!("[kernel] PageFault in application..."); // 实际应检查PTE状态
}
// ... existing code ...
```

2. **交换信息存储**
  - 通常利用PTE的保留位存储磁盘位置信息
  - 交换页面的PTE格式示例：
  ```
  | V=0 | 保留位(存储磁盘位置) | 其他标志位
  ```

3. **硬件行为**
   - MMU发现V=0时触发PageFault异常
   - stval寄存器记录故障地址
   - scause区分Load/Store类型

完整实现需要扩展PTE处理逻辑，包括：
- 换出时清除V位并记录磁盘位置
- 换入时从磁盘加载并恢复V位
- 更新页表后执行`sfence.vma`同步TLB

## 双页表与单页表

### 在单页表情况下，如何更换页表

- 通过修改`satp`(Supervisor Address Translation and Protection)寄存器实现
- 内核态下直接写入新页表的物理地址和模式：
  ```rust
  unsafe { satp::write(ppn, mode) };
  ```
- 需要配合`sfence.vma`指令刷新TLB

### 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）

- 利用页表项的权限位(PTE_U)：
  - 内核页面设置`PTE_U=0`(用户态不可访问)
  - 用户页面设置`PTE_U=1`
- 在`trap_handler`中通过`scause`识别非法访问并终止进程

### 单页表有何优势？（回答合理即可）

- 上下文切换开销小（无需切换页表）
- TLB利用率更高（共享内核映射）
- 系统调用/中断处理更快（无页表切换）
- 实现简单，适合嵌入式等资源受限场景

### 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？

- 双页表更换时机
  - 用户态 → 内核态：进入陷阱时
  - 内核态 → 用户态：陷阱返回前
  - 进程切换时：需同时切换用户页表
   
- 单页表系统的更换策略建议
  - 仅在进程切换时更换：
  - 保持内核映射常驻，通过权限位隔离保护
